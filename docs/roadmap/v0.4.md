# v0.4 — Профиль

**Цель:** раздел «Профиль» (5-й нижний таб) — точка входа во всё, что связано с *моим взаимодействием с командой*. Симметричен для организатора и игрока — оба заходят в свой профиль, чтобы посмотреть свою статистику, свои финансы, свои приглашения, и переключаться между командами. Старая v0.5 «Профиль» удаляется, её содержимое переехало сюда. v0.4 «Финансы» сдвинулась в [v0.5](v0.5.md).

**Итерации:** 43, 44, 45, 46 (сквозная нумерация; v0.3 закрылась на 42).

---

## Модель профиля (один источник, два режима)

Принципиальный момент: профиль игрока — **один источник данных** (запись в `users` + поля членства в `team_memberships`). У него два режима отображения:

- **Личный профиль** — то, что игрок видит у себя в разделе «Профиль». Полный набор полей (контакты, дата рождения, шейп, амплуа, номер и т.д.), редактируется самим игроком. Видны личные финансы и статистика по активной команде.
- **Публичный профиль** (`/squad/[user_id]`, уже существует с v0.2) — то, что другие участники команды видят, открывая карточку игрока в составе.
  - Для **другого игрока команды** — без sensitive-полей: статистика и общие данные есть, финансы скрыты.
  - Для **организатора** — расширенный публичный профиль: всё то же + финансы игрока + возможность редактировать поля игрока (используется, когда сам игрок не пользуется приложением — например, голосует через бота).

Это не два профиля, а одно состояние с разными «правами просмотра/редактирования». Источник правды — таблицы `users` + `team_memberships`; режим определяется тем, кто и откуда смотрит.

## Каркас экрана `/profile`

- **Шапка**: аватар, ФИО, под ним — pill роли в активной команде («Организатор» / «Игрок») и номер `#N` (если задан в этой команде).
- **Карточка контактов**: телефон, e-mail, telegram-username. Каждое поле со значком слева, тап → редактирование. Под карточкой — общий помет «Контакт виден команде».
- **Селектор активной команды**: строка-карточка под шапкой («Активная команда: ХК Север · Организатор ›»). Тап → bottom-sheet со списком всех `memberships`, чек напротив активной. Переключение пишет в `useActiveTeamStore` и рассылает `qc.invalidateQueries()` — этот механизм уже работает в текущем `/profile`, переносим как есть. Подэкраны профиля (статистика, финансы, приглашения) получают данные именно по активной команде.

## Личные разделы

Под шапкой — список пунктов-плиток или строк, каждый ведёт на подэкран `/profile/<...>`.

1. **Моя карточка** (`/profile/edit`) — редактирование своего профиля. Набор полей **ровно тот же**, что доступен в текущем редактировании публичного профиля игрока организатором ([/squad/[user_id]/edit](src/app/<tabs>/squad/<user_id>/edit/page.tsx)): имя, фото-аватар, дата рождения, контакты, bio, шейп, амплуа, номер. Игрок редактирует те же поля, что организатор может редактировать у него; разница только в правах доступа — игрок редактирует только своё.
2. **Моя статистика** (`/profile/stats`) — личная игровая статистика **по активной команде**: явка, голы, передачи, штрафы, очки за событие. Технически — тот же `PlayerStatsTab`, что используется в публичном профиле, но без `user_id` параметра (берём `me.user.id`).
3. **Мои финансы** (`/profile/finance`) — личное финансовое положение **по активной команде**: сколько я должен команде / сколько команда должна мне, список последних платежей и долгов. Аналог `PlayerFinanceTab`, источник — `GET /api/teams/me/members/[user_id]/finance` с подстановкой своего id.
4. **Приглашения и заявки** (`/profile/invites`) — личный инбокс игрока. Симметрично организаторскому экрану `/squad/requests`:
   - **Входящие приглашения** — команды, которые позвали меня (`team_join_requests.kind='invite'`, направленные на мой `user_id`).
   - **Исходящие заявки** — мои подачи в команды (`team_join_requests.kind='request'` за моим авторством), статусы pending/approved/rejected.
   - Сверху на странице (или кнопкой в шапке инбокса) — CTA **«Подать заявку в команду»**: открывает список всех команд, доступных в приложении, с поиском по названию. Выбор команды → POST создаёт заявку с `kind='request'`.
5. **Поддержка** (`/profile/support`) — пункт-заглушка. Реализация в post-MVP. На v0.4 — открывает soon-плашку с текстом «Поддержка появится позже».
6. **Политика конфиденциальности** (`/profile/privacy`) — пункт-заглушка. На v0.4 — soon-плашка. Решение, что туда класть (внешний URL или встроенный текст), фиксируем при реализации этого пункта.

## Чего в `/profile` нет

- **Командных настроек** — они в `/squad/settings` (закрыты в v0.3, итерация 41).
- **Командной статистики / тактики / медиа всей команды / турниров** — раздел «Команда» уже их закрывает (тактика и турниры — в post-MVP).
- **Личной галереи медиа** — отдельного `/profile/media` не делаем; общая галерея команды и фильтр «загружено мной» (если потребуется) живут в `/squad/media`.
- **Кнопки «Выйти из аккаунта»** — пока работаем внутри Telegram, авторизация происходит автоматически через `initData` на каждом запросе; «выйти» не нужно.
- **Личных push-настроек, отдельных toggle'ов видимости каналов контактов** — настройки уведомлений и тонкая настройка приватности контактов вынесены в post-MVP (см. «Настройки уведомлений» в post-mvp.md).

## Что нужно новое (будем специровать на итерациях)

- API `GET /api/me/invites` — список моих исходящих заявок и входящих приглашений по всем командам (а не только активной).
- API `POST /api/me/invites/[id]/decide` — принять/отклонить полученное приглашение.
- API `POST /api/me/join-requests` — подать заявку в команду по её id.
- API `GET /api/teams/available` (или расширение `/api/teams/search`) — список всех команд для CTA «Подать заявку», с поиском по названию.
- Подэкраны `/profile/edit`, `/profile/stats`, `/profile/finance`, `/profile/invites` — тонкие обёртки над переиспользуемыми компонентами + специфичный UX инбокса игрока.
- Личный режим редактирования: для игрока поля — те же, что у организатора в `/squad/[user_id]/edit`, но запросы идут через эндпоинты, защищённые правом «изменять только себя» (а не `requireOrganizer`). Скорее всего — новый `PATCH /api/me` (либо параметр в существующем endpoint) и `POST /api/me/avatar/sign`.

## ✅ Итерация 46 — Приглашения и заявки игрока

Личный инбокс игрока: входящие приглашения от команд + мои исходящие заявки в команды, плюс CTA «Подать заявку в команду» с поиском по списку.

- ✅ 46.1 `GET /api/me/invites` (`requireUser`): возвращает заявки и приглашения, где игрок — субъект (`team_join_requests.user_id = me.id`). Группировка по `kind`: `kind='request'` — мои заявки (исходящие); `kind='invite'` — приглашения мне (входящие). В выдачу — `id, team_id, team_name, team_logo_url, kind, status, decided_at, created_at`. Сортировка `created_at desc`.
- ✅ 46.2 DTO: `MyInviteItem`, `MyInvitesResponse` в `src/types/api.ts`.
- ✅ 46.3 `POST /api/me/invites/[id]/decide` (`requireUser`): принять/отклонить **входящее** приглашение (`kind='invite'`) — для самого приглашённого игрока. При approve — создаёт membership с `role='player'`, обновляет статус заявки на `approved`. При reject — `rejected`. Запреты: уже состоит в этой команде / уже решено → 409.
- ✅ 46.4 `POST /api/me/join-requests` (`requireUser`): подать заявку (`kind='request'`) в указанную команду по `team_id`. Защита: если уже состоит → 409; если уже есть pending по этой команде → 200 idempotent.
