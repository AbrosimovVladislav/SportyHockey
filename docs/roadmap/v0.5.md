# v0.5 — Финансы

Полноценный раздел «Деньги» для организатора. Хаб с балансом и быстрыми действиями, экран всех операций с фильтрами, балансы игроков, срез за период, аналитика. Учёт без онлайн-оплат — только ручной ввод. Все данные считаются поверх единой ленты `finance_transactions`; долги, переплаты, депозиты — вычисляемые разрезы, а не отдельные записи.

**Оплата игрока за событие** остаётся только на экране события (`PaymentSheet`, есть с v0.1) — это всегда привязка к конкретному событию, ввод вне его контекста неудобен. На хабе доступны 4 быстрых действия для операций, **не привязанных** к событию: Депозит, Аренда, Возврат игроку, Покупка инвентаря.

Каждый из четырёх sheet'ов поддерживает три режима — `create` из quick-action, `edit` с предзаполнением при тапе на соответствующую карточку в `/money/transactions`, `delete` кнопкой внутри. Отдельный transaction-card-sheet не делаем.

**Итерации:** 48, 49, 50, 51, 52, 53, 54, 55, 57, 58, 59 (сквозная нумерация; v0.4 закрылась на 47). Тестовая итерация (была 56) перенесена в конец и переименована в 59 — полная обкатка делается после ledger-рефакторинга 58, иначе чек-лист придётся переделывать.

## ✅ Итерация 51.1 — Долг по аренде, статус оплаты, venue picker

Финансовая модель раскладывается на «деньги команды» и «обязательства»: расчётный баланс = `на руках + долги игроков − переплаты игрокам − долги аренам`. Каждое событие с указанной `arena_cost` автоматически создаёт долг перед площадкой ровно до момента, пока его не оплатили (полностью). На странице события и в picker'е событий статус оплаты виден сразу; редактирование события включает и стоимость аренды, и взнос игрока; в bottomsheet «Аренда» площадка выбирается из справочника venues (свободный ввод убран).

- ✅ 51.1.1 Миграция `events_arena_paid_amount`: колонка `events.arena_paid_amount numeric NOT NULL DEFAULT 0` — сумма фактически оплаченного. Бэкфилом проставляется из `finance_transactions` (`type=expense, category=arena, event_id IS NOT NULL`), сгруппированных по `event_id`. Регенерирован `src/types/db.ts`.
- ✅ 51.1.2 `POST /api/finance`, `PATCH /api/finance/[id]`, `DELETE /api/finance/[id]`: после изменения транзакции с `type=expense, category=arena, event_id` пересчитывают `arena_paid_amount` для затронутого события (старого + нового при правке). Helper `syncArenaPaidAmount(sb, eventId)` в `src/lib/sync-arena-paid.ts`.
- ✅ 51.1.3 DTO: `EventDto.arena_paid_amount: number` (всегда есть, дефолт 0). `/api/events` и `/api/events/[id]` возвращают поле. `TeamBalanceBreakdown` — `arenas_this_month` заменён на `arena_debts: number`.
- ✅ 51.1.4 `computeTeamBalance` в `src/lib/team-finance.ts`: убран расчёт `arenas_this_month`, добавлен `arena_debts = ∑ max(0, event.arena_cost − event.arena_paid_amount)` по всем не отменённым событиям. Формула баланса: `total = on_hand + debts − overpayments − arena_debts`.
- ✅ 51.1.5 BalanceCard и i18n: подплитки 2×2 — «На руках» (нейтр.) / «Долги игроков» (зелёный, плюс) / «Переплаты игрокам» (красный) / «Долги аренам» (красный, новая) вместо «Аренды этого месяца». Подпись большого числа — «Расчётный баланс».

## Итерация 58 — Ledger «кто → кому», депозиты площадкам, «Прочее» в детализации

Финансовое ядро переводится в общий ledger: каждая транзакция — это перевод между двумя счетами (`team`, `user`, `venue`, `external`). Модель снимает разделение «оплата за событие vs депозит площадке» — одна и та же запись, с `event_id` или без; даёт «Прочее» как агрегат по external-балансам; делает запрет переплаты конкретного события естественной серверной проверкой. Параллельно в верх `/money` ставится третья строка `Прочее` в обеих детализациях.

**Гарантия:** командный баланс (`total`) после рефакторинга численно равен старому. Формула остаётся `total = on_hand + owed_to_us − owed_by_us`. Касса считается как `Σ(transfer to=team) − Σ(transfer from=team)`. Меняется только агрегирование арендных долгов/переплат: вместо per-event теперь per-venue, поэтому депозит/переплата на одном событии гасит долг на другом за той же площадкой. На total это не влияет (`Σ paid − Σ cost` одинаково при любой группировке).

**Маппинг старых записей в новые поля** (используется в бэкфилле миграции):

| Старое (`type`, `category`, `user_id`, `event_id`) | Новое (`kind`, `from_kind` → `to_kind`) |
|---|---|
| `player_payment`, user_id=U, event_id?         | `transfer`, `user(U)` → `team`     |
| `expense`, `arena`, event_id=E                  | `transfer`, `team` → `venue(events.venue_id)`, `event_id=E` |
| `expense`, `inventory`/`uniform`/`other`        | `transfer`, `team` → `external(label=category)`            |
| `refund`, user_id=U                             | `transfer`, `team` → `user(U)`     |
| `adjustment`, user_id=U                         | `adjustment`, `to_user_id=U` (одна сторона) |

### Структура

- 58.1 Миграция `finance_transactions_ledger` через Supabase MCP `apply_migration`: добавлены `kind text NOT NULL DEFAULT 'transfer'`, `from_kind text`, `to_kind text`, `from_user_id uuid REFERENCES users(id)`, `to_user_id uuid REFERENCES users(id)`, `from_venue_id uuid REFERENCES venues(id)`, `to_venue_id uuid REFERENCES venues(id)`, `external_label text`. CHECK-инварианты: для `kind='transfer'` — обе стороны заполнены ровно одним FK или `external_label`; для `kind='adjustment'` — заполнено только `to_user_id`. Бэкфилл best-effort по таблице маппинга — на старых записях не зацикливаемся (всё тестовое), главное чтобы CHECK не упал. Регенерация `src/types/db.ts` через `mcp__plugin_supabase_supabase__generate_typescript_types`. Старые `type` / `category` оставлены как denormalized зеркало на одну-две итерации, чтобы не править все читалки одной волной; дропаем после стабилизации.
- 58.2 `src/lib/team-finance.ts`: `computeTeamBalance` переписан на ledger. `on_hand` — через `to_kind='team'` / `from_kind='team'`. Балансы игроков — через `from_kind='user'` (взнос) и `to_kind='user'` (refund). Баланс площадки считается **per-venue**: `paid_v = Σ amount транзакций с `to_kind='venue', to_venue_id=v` (плюс historic `from_kind='team' to_kind='venue'` без события и с событием), `cost_v = Σ arena_cost событий с `venue_id=v` (≠ cancelled, `starts_at ≤ asOf`). `arena_debts = Σ max(0, cost_v − paid_v)`, `arena_overpayments = Σ max(0, paid_v − cost_v)`. External-счета: `external_overpayments = Σ max(0, paid_to_ext_label − received_from_ext_label)` и зеркальный `external_receivables`. Для PoC обе суммы будут 0, но место есть.
- 58.3 Типы `TeamBalanceDetails` расширены: `owed_by_us.external_overpayments: number`, `owed_to_us.external_receivables: number`. `TeamBalance` и `*Response`-обёртки наследуют автоматически.
- 58.4 `/api/finance` POST/PATCH: Zod-схема принимает новый ledger-формат — `kind`, `from_kind`/`to_kind`, соответствующие IDs/label. Старый формат (`type`, `category`, `user_id`, `event_id`) поддерживается как input-адаптер: на входе нормализуем в новые поля по таблице маппинга (чтобы хуки/sheet'ы можно было перевести постепенно). Запрет переплаты конкретного события: для записи с `to_kind='venue' + event_id` проверяем `Σ amount существующих транзакций to_venue+event_id` (с поправкой на собственную сумму при edit); если превысит `arena_cost` — 409 с сообщением «событие уже оплачено, для депозита уберите привязку».
- 58.5 `/api/finance/balance`, `/api/finance/analytics`, `/api/finance/report` отдают новые `details.owed_by_us.external_overpayments` и `details.owed_to_us.external_receivables`. Структура ответа в остальном без изменений.
- 58.6 `src/components/finance-sheet/arena-sheet.tsx`: поле «Событие» — опциональное, placeholder «Без события — депозит площадке». Когда событие выбрано — venue вычисляется из `event.venue_id` и блокируется. Когда не выбрано — venue выбирается свободно из справочника (как и сейчас). Локальная проверка против переплаты события — зеркало серверной 409.
- 58.7 `src/components/balance-details-card.tsx`: убрана фильтрация `value > 0`. Карточка показывает все переданные строки, в том числе нулевые. Скрывается только если items пуст (этот случай теперь не возникает — всегда передаём 3 строки).
- 58.8 `src/app/(tabs)/money/page.tsx`: третья строка в обеих карточках. «Мы должны» = Площадке / Игрокам / **Прочее** (`external_overpayments`). «Нам должны» = Игроки / Переплаты площадкам / **Прочее** (`external_receivables`).
- 58.9 i18n в `src/i18n/ru.ts`: новые ключи `money.balance.details.weOweOther` («Прочее»), `money.balance.details.theyOweOther` («Прочее»).
