# v0.5 — Финансы

Полноценный раздел «Деньги» для организатора. Хаб с балансом и быстрыми действиями, экран всех операций с фильтрами, балансы игроков, срез за период, аналитика. Учёт без онлайн-оплат — только ручной ввод. Все данные считаются поверх единой ленты `finance_transactions`; долги, переплаты, депозиты — вычисляемые разрезы, а не отдельные записи.

**Итерации:** 48, 49, 50, 51, 52, 53 (сквозная нумерация; v0.4 закрылась на 47).

## Итерация 52 — Балансы игроков `/money/players`

Срез по всем игрокам команды на «сегодня». Тап ведёт в существующий публичный профиль (`/squad/[user_id]`) — у организатора там уже видна вкладка «Финансы». Корректировка баланса (`adjustment`) — отсюда же.

- 52.1 `GET /api/finance/players` (`requireUser` + активная команда): возвращает массив `{ user_id, first_name, last_name, avatar_url, balance, total_charged, total_paid, last_payment_at, status }`. `status` = `'debtor'` если `balance > 50`, `'overpaid'` если `balance < -50`, `'closed'` если `|balance| ≤ 50 && total_charged > 0`, `'inactive'` если `total_charged == 0 && total_paid == 0`. Источник — `computeTeamBalance` (массив `players[]`, уже есть).
- 52.2 DTO `PlayerBalanceItem`, `PlayersBalanceResponse` + хук `usePlayersBalance()`. Инвалидация — после любой мутации над `finance_transactions`.
- 52.3 Экран `/money/players/page.tsx`: `LightHeader` «Балансы игроков», back на `/money`. Sticky `ContentTabs`: «Все / Должники / С депозитом / Закрыты» — локальный фильтр по `status`. Список карточек в стиле `MemberRow` (аватар, имя, статус-чип «Должен 1 200 ₽» / «Депозит 500 ₽» / «Закрыто», справа — баланс крупно со знаком).
- 52.4 Сортировка по умолчанию: должники сверху по убыванию долга, потом переплаты по убыванию, потом закрытые. Внутри «Все» — этот же порядок. Сортировка фиксированная, переключатель «по имени» — в post-MVP.
- 52.5 Тап на карточку игрока ведёт на `/squad/<user_id>` — это уже существующий публичный профиль организатора с вкладками Обзор/Финансы/Статистика. Никаких новых экранов профиля не делаем.
- 52.6 Компонент `src/components/finance-sheet/adjustment-sheet.tsx` (или дополнение `expense-sheet`): sheet с фиксированным игроком (выбран на карточке), полем «Сумма» со знаком (segmented `+/−`), полем «Причина». Тип отправляется как `'adjustment'`. Открывается с карточки игрока — отдельной кнопкой «Скорректировать баланс».
- 52.7 На хабе `/money` строка «Балансы игроков» подключается к этому экрану.
- 52.8 i18n `money.players.*`: заголовок, табы (Все / Должники / С депозитом / Закрыты), статус-чипы, кнопка «Скорректировать баланс», тексты adjustment-sheet'а.

- 53.1 `PATCH /api/finance/<id>` (`requireUser` + активная команда + organizer-check): обновление транзакции. Меняется всё кроме `type` — если ошиблись типом, проще удалить и создать заново. ## Итерация 54 — Аналитика и прогноз `/money/analytics`

Графики и прогноз. Самая дорогая итерация: 5 графиков на `recharts` (либо нативный canvas, если не хотим лишнюю зависимость) + прогноз поступлений на основе средней явки. Если ужмёт по времени — режем пополам, оставляем графики, прогноз отдельно.

- 54.1 `GET /api/finance/analytics?from&to` (`requireUser` + активная команда): возвращает массивы помесячных (или понедельных при коротком периоде) точек для пяти графиков: `balance_over_time` (накопительная линия по on_hand), `collections_per_month`, `expenses_per_month_by_category` (с разбивкой arena/inventory/uniform/other для стек-бара), `debts_over_time`, `deposits_overpayments_over_time`. Внутри — один SQL-запрос всех транзакций периода + разворот в массив дней.
- 54.2 `GET /api/finance/forecast?horizon=1|2|3` (`requireUser` + активная команда): прогноз на 1/2/3 месяца вперёд. Алгоритм: для каждого будущего события (`start_at > today`, `archived_at IS NULL`) ожидаемая явка = средняя посещаемость за последние 6 событий того же типа; ожидаемый сбор = ожидаемая явка × `cost_per_player`.
