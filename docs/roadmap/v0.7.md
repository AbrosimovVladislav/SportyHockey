**Цель:** версия, готовая к широкому outreach на 250+ команд. Полная обкатка MVP запускает наполнение версии — каждый слабый поинт, найденный при прогоне сценария, превращается в конкретный пункт. Плюс outreach-функции, которые показываем при запуске.

## Итерация 67 — Полная обкатка MVP

E2E-проверка **всего** приложения после v0.5 + v0.6 — не только финансов. Сценарий из v0.5 был финансовоориентированный; здесь расширяем до полного покрытия и сверяем. Эта итерация — стартовый триггер полировки: каждое расхождение/UX-баг/слабая формулировка превращается в отдельный пункт ниже по списку.

- 67.0 Сценарий в [docs/testing/scenario.md](../testing/scenario.md): расширить за пределы финансов. Разделы: «Команда» (приглашения, роли, переключение активной команды, заявки), «Игроки» (профили personal/public, статусы участия, placeholder-игроки), «События» (создание, редактирование, отмена, перенос, attendance-flow, голосование), «Статистика» (счёт, голы, ассисты, удаления, сводки), «Главная» (шапка, карточка ближайшего события для тренировки и для игры, три таба статистики, quick-actions organizer/player), «Финансы» (4 quick-action sheet'а, депозиты площадкам, балансы игроков, операции, срез, аналитика). Под каждый экран — действия + ожидаемые значения.
- 67.0a Перерасчёт численных ожиданий под новую модель после v0.5: per-venue агрегирование арендных долгов/переплат; external = 0 в детализации (строка «Прочее» скрывается); формула баланса `total = on_hand + owed_to_us − owed_by_us`.
- 67.0b Дописать ожидания для новой главной: какие топ-5 игроков должны выйти у тест-данных, какой last_game (счёт + ассисты + удаления), какая сводка команды (включая `balance`).
- 67.1 Очистка пилотной команды: оставить участников, удалить все события, финансы, статистику, `result_points`, `event_penalties`. Скрипт миграции либо ручная зачистка через интерфейс.
- 67.2 Прогон сценария через приложение (без обхода API — действия только через UI; на финансах — sheet'ы и валидации; на событиях — голосование, явка, статистика; на главной — сверка с числами).
- 67.3 Сверка наблюдаемого с ожидаемыми значениями. Все расхождения и слабые места — в backlog ниже как отдельные итерации (68+).

## Направления (без детализации до подпунктов)

### Полировка

- Пул задач из фидбека пилотов + результатов обкатки 67.3 — наполняется по ходу.

### Бот в групповом чате команды

Эпик: [features/notifications.md](../features/notifications.md).

- Команда `/connectchat` в боте, привязка группового чата команды.
- Посты о событиях с inline-голосованием в чате (вместо/в дополнение к личке).
- Утренний дайджест organizer + напоминание игроку «Ты завтра играешь» за 24ч.

### Постеры событий

Эпик: [features/social-sharing.md](../features/social-sharing.md).

- Шаблоны постеров (отдельный дизайн-handoff).
- API генерации PNG через `@vercel/og` / `satori`.
- Шаринг через Telegram native share / скачивание.

### Публичные события и лендинг

Эпик: [features/events.md](../features/events.md), [features/social-sharing.md](../features/social-sharing.md).

- В форме события — toggle `public`.
- Публичная страница события на `/public/events/[id]` (обычный web, вне Mini App).
- Постер ведёт на лендинг.
- Опционально: запись стороннего человека (без аккаунта).

### Instagram

Эпик: [features/social-sharing.md](../features/social-sharing.md).

- OAuth-flow для подключения Instagram Business аккаунта команды.
- Постинг события (фото + caption) через Instagram Graph.
- Автогенерация поста о результатах матча.

### Аналитика

- PostHog: setup, identification (по `telegram_id`), события `team_created / event_created / voted / attended_marked / transaction_added`.
- Funnels и retention-метрики — список фиксируем на handoff.
