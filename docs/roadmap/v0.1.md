## Итерация 13 — Состав тренировки: явка и оплата

Эпик: [features/roster-day.md](../features/roster-day.md). Источник дизайна — [design_handoffs/dh_event_v1](../../design_handoffs/dh_event_v1). Внутри страницы **нет табов** — деление пятёрок и статистика вынесены в отдельные итерации (14, 15). Здесь только «Явка и оплата».

### Доработки (база и форма создания события)

- ✅ 13.1 Миграции БД (применены `attendees_payment_arena_jersey`):
  - `team_memberships`: добавлены `jersey_number int NULL`, `position text NULL CHECK (position IN ('forward','defender','goalie'))`.
  - `venues`: добавлено `cost_per_arena numeric NULL` — стандартная цена аренды арены (то, что команда платит арене).

### Основной экран `/events/[id]/attendees`

- [ ] 13.5 API `GET /api/events/[id]` обогащается:
  - В каждом `attendee` — `jersey_number: number | null`, `position: 'forward'|'defender'|'goalie'|null`, `showed_up: boolean | null`, `paid_amount: number | null` (вычисляется JOIN'ом к `finance_transactions` по `(event_id, user_id, type='player_payment')`), `payment_claim: boolean`.
  - В корне ответа — `payments: { paid_count, partial_count, debt_count, collected, target }`. Расчёт **только среди `vote === 'going'`**: target = `going_count × cost_per_player`; `paid` — `paid_amount >= cost`, `partial` — `0 < paid < cost`, `debt` — `paid` пусто или `0`. Если `cost_per_player` отсутствует — `target = 0`, finance-card скрывается.
- [ ] 13.6 API `POST /api/events/[id]/payment` (organizer-only) — `{ user_id, amount: number | null }`:
  - `null` или `0` → `DELETE FROM finance_transactions WHERE event_id=? AND user_id=? AND type='player_payment'`; `event_attendances.payment_claim = false` (сбрасываем пинг).
  - `> 0` → `INSERT … ON CONFLICT (event_id, user_id) WHERE type='player_payment' DO UPDATE SET amount` в `finance_transactions(type='player_payment', team_id, event_id, user_id, amount, created_by)`; `event_attendances.payment_claim = false`. Сумма может быть > `cost_per_player` (переплата), это допустимо.
  - Сумма «оплачено» теперь — единственный источник правды через `finance_transactions`. Поле `event_attendances.paid_amount` НЕ ТРОГАЕМ (legacy).
- [ ] 13.7 API `POST /api/events/[id]/attendance` (organizer-only) — `{ user_id, showed_up: boolean }` → upsert `event_attendances.showed_up`. Отдельный флаг от `vote=going`: организатор фиксирует факт прихода после события.
- [ ] 13.8 API `POST /api/events/[id]/payment-claim` (player-only, любой member команды) — «Я уже оплатил, напомните оргу»:
