# v0.1 — PoC

**Цель:** проверить ядро гипотезы на 1–3 пилотных командах. Организатор ведёт события, явку и финансы в одном месте; игроки голосуют через бот без открытия Mini App.

**Итерации:** 6, 7, 8, 9, 10.

---

## ✅ Итерация 6 — Онбординг + команда (минимально)

Эпики: [features/onboarding.md](../features/onboarding.md), [features/team.md](../features/team.md)

- ✅ 6.1 Welcome screen `/onboarding` — выбор роли (organizer / player)
- ✅ 6.2 Organizer flow: поле «Название команды» (без лого на PoC), кнопка «Создать команду»
- ✅ 6.3 API `POST /api/teams` — создаёт `team` + `team_membership(role=organizer)` для текущего user (zod-валидация: длина 2–50)
- ✅ 6.4 API `GET /api/me` — текущий user + список memberships (`team_id`, `team_name`, `role`) + `invite_link` (только для organizer)
- ✅ 6.5 Gate в `(tabs)/layout.tsx`: если у user нет memberships → `replace('/onboarding')`; в `/onboarding` — обратно `replace('/')` после получения membership
- ✅ 6.6 Player flow без ссылки: empty state «Попроси организатора прислать ссылку приглашения»
- ✅ 6.7 Bot: handler `/start team_<uuid>` — upsert user, создаёт `team_membership(role=player)` (или сообщает «уже в команде»), отвечает с inline-кнопкой «Открыть Mini App» (через `MINI_APP_URL`)
- ✅ 6.8 Squad screen `/squad` + API `GET /api/teams/me/members` — список членов команды (avatar, имя, @username, роль)
- ✅ 6.9 Profile screen `/profile` — карточка user, карточка команды; для organizer — кнопка «Скопировать ссылку приглашения» (формат `https://t.me/<BOT_USERNAME>?start=team_<uuid>`)

## ✅ Итерация 7 — События: API (CRUD)

Эпик: [features/events.md](../features/events.md)

UI событий — отдельной итерацией после прихода дизайн-системы и конкретных экранов.

- ✅ 7.1 `requireOrganizer(req)` в `src/lib/auth.ts` → `{ user, team_id }` или 403; находит team_id текущего user'а по `team_memberships(role=organizer)`
- ✅ 7.2 Заглушки нотификаций `src/lib/notify.ts`: `notifyEventCreated`, `notifyEventUpdated`, `notifyEventCancelled` — пустые функции с `// TODO: 8.x — реализовать рассылку`
- ✅ 7.3 API `GET /api/events` — события команды текущего user (по team_id), кроме `status=cancelled`; сортировка `starts_at ASC`; в каждом событии счётчик явки `{ going, maybe, not_going }` из `event_attendances`
- ✅ 7.4 API `POST /api/events` — organizer-only, zod-валидация (`type`, `starts_at`, `title?`, `ends_at?`, `venue_text?`, `cost_per_player?`, `description?`); создаёт event с `team_id`, `created_by`; вызывает `notifyEventCreated`
- ✅ 7.5 API `GET /api/events/[id]` — detail (поля события + счётчик явки); 404 если не в команде user'а
- ✅ 7.6 API `PATCH /api/events/[id]` — organizer-only; все поля optional + `status?` (только `scheduled` / `cancelled`); вызывает `notifyEventUpdated` или `notifyEventCancelled` в зависимости от изменения
- ✅ 7.7 Типы DTO в `src/types/api.ts`: `EventDto`, `EventDetailDto`, `CreateEventRequest`, `UpdateEventRequest`, `EventsListResponse`
