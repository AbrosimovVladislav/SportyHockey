# v0.6 — Главная

Главный экран приложения — первый таб «Команда» (`/(tabs)/page.tsx`). До v0.6 здесь была пустая `Screen`-заглушка. Полная обкатка MVP, которая раньше планировалась в конце этой версии, переехала в [v0.7](v0.7.md) — она открывает полировку, а не закрывает разработку Главной. Делаем дайджест в один проход сверху вниз:

1. **Шапка** — логотип команды + название (без подписи сезона), иконка-колокольчик справа (заглушка → `/notifications/soon` до отдельного эпика).
2. **Карточка ближайшего события** — фон-картинка, бейдж типа («Ближайшая тренировка» / «Ближайшая игра»), для игры — пара «наша команда vs соперник» (логотип + название с каждой стороны; для соперника логотипа в схеме нет — заглушка), дата · время, иконка-локация + название площадки, три метрики (явка / взнос с игрока / места), CTA «Открыть событие».
3. **Quick actions 2×2** — четыре важных действия. У организатора один набор, у игрока — другой.
4. **Блок «Ключевая статистика»** — карточка с тремя табами:
   - **Топ-5 игроков** — топ по очкам (Г + П) **только в играх** (по `events.type='game'`).
   - **Последний матч** — счёт нашей команды vs соперник + ассисты с каждой стороны + минуты удаления. Метрики, которых у нас нет в модели (броски, вбрасывания, силовые приёмы, сэйвы), **не показываем**.
   - **Сводка команды** — шесть метрик: матчей сыграно, тренировок проведено, побед, заброшенных шайб, пропущенных шайб, финансовый баланс. «Средняя явка» / «Сбор денег» в первой версии **не** показываем (на скриншоте были, но юзер заменил на «Финансовый баланс» и убрал явку).

Карточка ближайшего события **адаптируется под тип**: тренировка — фон + название места + метрики; игра — добавляется пара логотипов с названиями над датой. Для соперника логотипа нет (`events.opponent_name` есть, а `opponent_logo_url` — нет), рисуем плейсхолдер-щит с инициалами. Для нашей команды берём `teams.logo_url` (есть в схеме).

Для игрока главная имеет ту же структуру, но отличается **набор quick-actions** и (опционально) **состав блока статистики**: вместо «Топ-5 / Последний матч / Сводка» можем оставить те же три таба — игроку они интересны как члену команды. Принимаем: те же три таба, отличается только quick-actions.

**Итерации:** 62, 63, 64, 65, 66 (сквозная нумерация; v0.5 закрылась на 60, итерация 61 «полная обкатка финансов» переехала в [v0.7](v0.7.md) как 67 «Полная обкатка MVP» — она стартует наполнение полировки и логически принадлежит следующей версии).

> Передизайн от 2026-06-08 (после первых трёх итераций): шапка раздела + карточка ближайшего события объединены в один full-width тёмно-зелёный hero-блок (как DarkHeader на /money) — это компонент `HomeHero`. Метрики «N из M / X ₽ / K мест» переехали в полупрозрачную карточку справа внутри hero. Quick-actions сжаты до двух горизонтальных плиток в строке («Создать событие», «Заявки»). Карточка «Ключевая статистика» получила фиксированную min-height 360 px — переключение табов больше не двигает layout. Подробности — в итерациях 62 / 63 / 64 ниже (пункты помечены «передизайн»).

## ✅ Итерация 64 — Блок «Ключевая статистика»: 3 таба

Карточка `KeyStatsCard` под quick-actions. Заголовок «Ключевая статистика», pill-табы («Топ 5 игроков» / «Последняя игра» / «Команда») через `FilterChips compact`. Контент таба — соответствующий компонент со своим empty-state. Один эндпоинт отдаёт сразу три набора данных.

Решения по схеме (по результатам ревизии перед кодом):

- `result_points.team_side` для игр = `'own'` / `'opponent'` (для тренировок — `'light'` / `'dark'`, мы их фильтруем).
- `result_points.type` = `'goal'` / `'assist'`. Голы соперника — без `user_id`.
- `event_penalties` существует, есть `minutes` и `team_side`. Подходит как есть.
- `events.outcome` автоматически пересчитывается из голов в [src/lib/event-outcome.ts](../../src/lib/event-outcome.ts), но только при наличии голов. Wins считаем по `outcome='win'`. Если игра «завершилась 0:0 без забитых голов», она не считается ни в выигрыши, ни в поражения.
- Метрики, которых нет в схеме (броски, вбрасывания, силовые приёмы, сэйвы) — не показываем. Юзер явно сказал не выдумывать.

- ✅ 64.1 `GET /api/team/dashboard-stats` в [src/app/api/team/dashboard-stats/route.ts](../../src/app/api/team/dashboard-stats/route.ts) (`requireUser` + активная команда). Один эндпоинт отдаёт `{ top_players, last_game, team_summary }`. Параллельные запросы: все события команды (для счётчиков и определения last_game), `result_points` всех игр с inner-join `events.team_id` + `type='game'` + `status != 'cancelled'` (для top-5 и для `goals_for/against`), `computeTeamBalance(team)` (для `balance`).
