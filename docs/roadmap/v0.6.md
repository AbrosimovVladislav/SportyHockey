# v0.6 — Главная

Главный экран приложения — первый таб «Команда» (`/(tabs)/page.tsx`). До v0.6 здесь была пустая `Screen`-заглушка. Делаем дайджест в один проход сверху вниз:

1. **Шапка** — логотип команды + название (без подписи сезона), иконка-колокольчик справа (заглушка → `/notifications/soon` до отдельного эпика).
2. **Карточка ближайшего события** — фон-картинка, бейдж типа («Ближайшая тренировка» / «Ближайшая игра»), для игры — пара «наша команда vs соперник» (логотип + название с каждой стороны; для соперника логотипа в схеме нет — заглушка), дата · время, иконка-локация + название площадки, три метрики (явка / взнос с игрока / места), CTA «Открыть событие».
3. **Quick actions 2×2** — четыре важных действия. У организатора один набор, у игрока — другой.
4. **Блок «Ключевая статистика»** — карточка с тремя табами:
   - **Топ-5 игроков** — топ по очкам (Г + П) **только в играх** (по `events.type='game'`).
   - **Последний матч** — счёт нашей команды vs соперник + ассисты с каждой стороны + минуты удаления. Метрики, которых у нас нет в модели (броски, вбрасывания, силовые приёмы, сэйвы), **не показываем**.
   - **Сводка команды** — шесть метрик: матчей сыграно, тренировок проведено, побед, заброшенных шайб, пропущенных шайб, финансовый баланс. «Средняя явка» / «Сбор денег» в первой версии **не** показываем (на скриншоте были, но юзер заменил на «Финансовый баланс» и убрал явку).

Карточка ближайшего события **адаптируется под тип**: тренировка — фон + название места + метрики; игра — добавляется пара логотипов с названиями над датой. Для соперника логотипа нет (`events.opponent_name` есть, а `opponent_logo_url` — нет), рисуем плейсхолдер-щит с инициалами. Для нашей команды берём `teams.logo_url` (есть в схеме).

Для игрока главная имеет ту же структуру, но отличается **набор quick-actions** и (опционально) **состав блока статистики**: вместо «Топ-5 / Последний матч / Сводка» можем оставить те же три таба — игроку они интересны как члену команды. Принимаем: те же три таба, отличается только quick-actions.

**Итерации:** 62, 63, 64, 65, 66 (сквозная нумерация; v0.5 закрылась на 60, итерация 61 «полная обкатка финансов» перенесена и переименована в 66 — обкатываем уже всё приложение целиком, не только финансы).

## Итерация 64 — Блок «Ключевая статистика»: 3 таба

Карточка `KeyStatsCard` под quick-actions. Сверху — заголовок «Ключевая статистика», под ним `ContentTabs` («Топ 5 игроков» / «Последняя игра» / «Команда»). Контент таба — соответствующая таблица. Все данные — одним запросом в `GET /api/team/dashboard-stats`.

- 64.1 `GET /api/team/dashboard-stats` (`requireUser` + активная команда): один эндпоинт, отдаёт три блока:
  - `top_players_by_points`: массив `{ user_id, first_name, last_name, avatar_url, jersey_number, goals, assists, points }` топ-5 по `points = goals + assists`, только из событий `type='game'`, не отменённых. Источник: `result_points` JOIN `events` WHERE `events.team_id=...` AND `events.type='game'` AND `events.status != 'cancelled'`; GROUP BY user_id, SUM goals + SUM assists.
  - `last_game`: ближайшая прошедшая игра — `{ event_id, our_score, opp_score, opponent_name, our_logo_url, opp_logo_url, our_assists, opp_assists, our_penalty_minutes, opp_penalty_minutes, played_on }`. Источник: `events` WHERE `type='game'` AND `status != 'cancelled'` AND `starts_at < now()` ORDER BY `starts_at DESC LIMIT 1`. Голы/ассисты считаются из `result_points` по `team_side='us'/'them'` + `type='goal'/'assist'`. Минуты удаления — из `event_penalties` SUM(`minutes`) с группировкой по стороне.
  - `team_summary`: `{ games_played, trainings_played, wins, goals_for, goals_against, balance }`. `games_played` = COUNT events `type='game'` AND `status='played'` (или просто `starts_at < now` AND `status != 'cancelled'`). `wins` = COUNT events с `outcome='win'`. `goals_for` / `goals_against` — суммы `result_points` `type='goal'` по `team_side='us'` / `'them'` в играх команды. `balance` = `computeTeamBalance(sb, teamId).total` (переиспользуем готовое).
- 64.2 DTO `HomeDashboardStatsResponse` в [src/types/api.ts](../../src/types/api.ts). Подтипы: `HomeTopPlayerRow`, `HomeLastGame`, `HomeTeamSummary`. Хук `useDashboardStats` в [src/hooks/use-dashboard-stats.ts](../../src/hooks/use-dashboard-stats.ts). Префикс ключа `dashboard-stats` инвалидируется в `use-create-event`, `use-update-event`, `use-delete-event`, `use-create-finance`, `use-update-finance`, `use-delete-finance`, а также в хуках, меняющих `result_points` / `event_penalties` (если такие есть — выяснить).
- 64.3 Компонент [src/components/home/key-stats-card.tsx](../../src/components/home/key-stats-card.tsx): белая карточка, заголовок «Ключевая статистика», `ContentTabs` (3 шт.), внутри — slot под активный таб. Состояние «нет данных» (нет игр у команды → пустые `top_players` и `last_game`; для `team_summary` отдаём нули) — каждый таб сам рисует свой empty state.
- 64.4 Таб «Топ 5 игроков» — компонент [src/components/home/top-players-table.tsx](../../src/components/home/top-players-table.tsx):
  - Заголовочная строка: «Игрок», «Г», «П», «Очки» (последние три выровнены вправо).
  - Строки 1–5: номер позиции, аватар (`avatar_url ?? photo_url`), имя + «#jersey_number», три числа справа. «Очки» — жирно, цветом `colors.success`.
  - Пустое: «Сыграно 0 игр» — иконка-кубок приглушённая.
- 64.5 Таб «Последняя игра» — компонент [src/components/home/last-game-tile.tsx](../../src/components/home/last-game-tile.tsx):
  - Верх: три колонки — логотип нашей команды + название (слева), счёт + дата (центр, крупно), логотип соперника + название (справа). Для соперника — щит-плейсхолдер с инициалами.
  - Под счётом — таблица из двух строк: «Голевые передачи» (наша N — соперник M), «Удаления (мин)» (наша N — соперник M).
  - Пустое: «Игр ещё не было».
- 64.6 Таб «Команда» — компонент [src/components/home/team-summary-tile.tsx](../../src/components/home/team-summary-tile.tsx):
  - Сетка 2×3 (6 плиток): иконка + заголовок + большое число. Плитки: «Матчей» (`games_played`), «Тренировок» (`trainings_played`), «Побед» (`wins`), «Шайб» (`goals_for`), «Пропущено» (`goals_against`), «Финансовый баланс» (`balance`, форматирование через `formatMoney`).
  - Цвет числа балансовой плитки: положительный → `colors.success`, отрицательный → `colors.error`, ноль — нейтральный.

## Итерация 66 — Полная обкатка MVP

E2E-проверка **всего** приложения после v0.5 + v0.6 — не только финансов. Сценарий из v0.5 был финансовоориентированный; здесь расширяем до полного покрытия и сверяем.

- 66.0 Сценарий в [docs/testing/scenario.md](../testing/scenario.md): расширить за пределы финансов. Разделы: «Команда» (приглашения, роли, переключение активной команды, заявки), «Игроки» (профили personal/public, статусы участия, placeholder-игроки), «События» (создание, редактирование, отмена, перенос, attendance-flow, голосование), «Статистика» (счёт, голы, ассисты, удаления, сводки), «Главная» (шапка, карточка ближайшего события для тренировки и для игры, три таба статистики, quick-actions organizer/player), «Финансы» (4 quick-action sheet'а, депозиты площадкам, балансы игроков, операции, срез, аналитика). Под каждый экран — действия + ожидаемые значения.
- 66.0a Перерасчёт численных ожиданий под новую модель после v0.5: per-venue агрегирование арендных долгов/переплат; external = 0 в детализации (строка «Прочее» скрывается); формула баланса `total = on_hand + owed_to_us − owed_by_us`.
- 66.0b Дописать ожидания для новой главной: какие топ-5 игроков должны выйти у тест-данных, какой last_game (счёт + ассисты + удаления), какая сводка команды (включая `balance`).
- 66.1 Очистка пилотной команды: оставить участников, удалить все события, финансы, статистику, `result_points`, `event_penalties`. Скрипт миграции либо ручная зачистка через интерфейс.
- 66.2 Прогон сценария через приложение (без обхода API — действия только через UI; на финансах — sheet'ы и валидации; на событиях — голосование, явка, статистика; на главной — сверка с числами).
- 66.3 Сверка наблюдаемого с ожидаемыми значениями. Все расхождения — списком.
- 66.4 Доводка по фидбеку обкатки: точечные правки UX, формулировок, валидаций.
