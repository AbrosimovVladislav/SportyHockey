# v0.3 — Прочие секции раздела «Команда»

**Цель:** закрыть оставшиеся секции раздела «Команда» поверх готового «Состава» (v0.2): главная раздела (хаб), Статистика, Тактика, Медиа, Настройки команды.

Раздел «Команда» (4-й нижний таб, бывший «Состав») получает **главную страницу-хаб** по образцу страницы события `/events/[id]`: шапка, сводка по команде и список секций. Сами секции (Статистика / Тактика / Медиа / Настройки) дозаполняются по итерациям; до реализации каждая открывает заглушку «Скоро».

**Итерации:** 36, 37, 38, 39, 40, 41 (сквозная нумерация; v0.2 закрылась на 35). Порядок 37→41 предварительный — подвинем по фидбеку пилотов. Тактика идёт последней как наименее проработанное направление (добрейнштормим перед стартом).

## Итерация 37 — Статистика и аналитика (командная)

Эпик: [features/stats.md](../features/stats.md)

Экран `/squad/stats` поверх готовой модели `result_points` (v0.2) и нового сохранённого исхода события. Светлая шапка с кнопкой назад и заголовком «Статистика и аналитика»; правую иконку фильтра не делаем — никакой фильтрации, кроме встроенных чипов на самом экране, в этой итерации нет. Под шапкой — два уровня переключателей: основные табы «Статистика / Аналитика» и под ними глобальные сегмент-чипы «Игры / Тренировки» (влияют на обе вкладки).

**База данных и пересчёт исхода события**

- 37.1 Миграция через Supabase MCP: добавить колонку `events.outcome` (enum `'win' | 'draw' | 'loss'`, nullable; для тренировок и для игр без зафиксированного счёта — `null`). Перегенерировать `src/types/db.ts`.
- 37.2 Хелпер `recomputeEventOutcome(eventId)` в `src/lib/event-outcome.ts`: считает счёт по `result_points` (тип `'goal'`, `team_side own/opponent`) и пишет результат в `events.outcome`. Вызывается из всех мутаций голов (`POST/PATCH/DELETE /api/events/[id]/goals[/goalId]`) и из логики смены статуса события. Существующие события на стенде один раз прогоняются скриптом через тот же хелпер.

**API и DTO**

- 37.3 API `GET /api/teams/me/stats?type=game|training` (`requireUser` + `getUserTeamId`): возвращает агрегаты команды за все завершённые события указанного типа.
- 37.4 DTO `TeamStatsResponse`:
  - `summary`: для типа `game` — `{ games_played, wins, goals, assists }`; для `training` — `{ trainings_played, goals, assists }` (без побед).
  - `players[]`: массив строк по членам команды с полями `user_id, first_name, last_name, photo_url, avatar_url, jersey_number, position, goals, assists, points, penalty_minutes`. Игроки без статистики тоже попадают (с нулями), чтобы фильтр по амплуа всегда показывал всех.
  - `analytics`: `{ total_points, points_distribution (top-3 + others), top3_efficiency, leaders (points/goals/assists/penalties), by_position (forwards/defenders/goalies — голы/передачи), top_combinations (пары assist→goal), top_penalties }`.
- 37.5 Хук `useTeamStats(type)` — `useQuery` с ключом `['team-stats', type]`.

**Вкладка «Статистика»**

- 37.6 Над контентом вкладок — единый сегмент-переключатель «Игры / Тренировки» (повторяет вид `ContentTabs`). При смене сегмента перезапрашивается `useTeamStats`.
- 37.7 Сетка карточек-метрик команды (новый компонент `stat-summary-card.tsx`) сверху: в режиме «Игры» — 2×2 (Игры, Победы, Голы, Передачи); в режиме «Тренировки» — 3 карточки в один ряд (Тренировки, Голы, Передачи).
- 37.8 Под карточками — `FilterChips` «Нападающие / Защитники / Вратари» (значения `forward/defender/goalie`). Выбор «Вратари» рендерит пустое состояние с пояснением, что вратарская статистика появится позже.
- 37.9 Таблица игроков — переиспользуем `PlayerStatsRow` (колонки Г / П / Ш): сортировка по очкам убыванию, тап по строке ведёт на `/squad/[user_id]`. Заголовок таблицы со столбцами Г / П / Ш — отдельная строка над списком.

**Вкладка «Аналитика»**

- 37.10 Карточка «Распределение очков команды» — донат-чарт с центральным числом «всего очков» и легендой из топ-3 игроков + «Остальные» (с процентами). Новый компонент `donut-chart.tsx`.
- 37.11 Карточка «Голы и передачи» — два вертикальных столбика разной высоты (зелёные оттенки) с подписями «N голов / N передач». Новый компонент `bar-pair.tsx`.
- 37.12 Карточка «Эффективность» (топ-3) — очки за игру у топ-3 игроков (медаль, аватарка, имя, значение с двумя знаками). Новый компонент `efficiency-top3.tsx`. В режиме «Тренировки» — «очки за тренировку».
- 37.13 Карточка «Лучшие по категориям» — Очки / Голы / Передачи / Штрафы (с иконкой строки, именем лидера и значением). Новый компонент `category-leaders.tsx`.
- 37.14 Карточка «Вклад по амплуа» — три строки с горизонтальным прогресс-баром «N голов / N передач» по группам Нападающие / Защитники / Вратари. Новый компонент `position-contribution.tsx`.
- 37.15 Карточка «Топ связок» — пары «ассистент → бомбардир» с количеством голов в паре. Считаются через `result_point_links` (assist_point → goal_point), сгруппированы по парам `(assist_user, goal_user)`. Новый компонент `top-combinations.tsx`.
- 37.16 Карточка «Самые удаляющиеся» — топ-3 по сумме штрафных минут из `event_penalties`. Новый компонент `penalty-leaders.tsx`.

**Подключение и тексты**

- 37.17 Пункт «Статистика и аналитика» в хабе раздела «Команда» (`/squad/page.tsx`) ведёт на `/squad/stats` вместо заглушки «Скоро».
- 37.18 i18n `teamStats.*`: заголовки экрана и обоих наборов вкладок, подписи карточек-метрик, лейблы фильтра амплуа, пустое состояние вратарей, заголовки и единицы измерения карточек аналитики.

## ✅ Итерация 38 — Медиа (общая галерея команды)

Эпик: [features/media.md](../features/media.md)

Общая галерея команды поверх готового медиа-функционала событий (v0.1) — лента всех медиа со всех событий в одном месте. Загрузка в этой итерации остаётся только на странице события, в общей галерее — просмотр и удаление. Права на удаление те же, что в событии: автор медиа или организатор. _(Возможность загрузки прямо в общей галерее без привязки к событию добавлена в 39.4.)_

- ✅ 38.1 API `GET /api/teams/me/media?from=&to=` (`requireUser` + `getUserTeamId`): возвращает все медиа команды с информацией о событии (id, тип, название, `starts_at`, `ends_at`, площадка) и о загрузившем (id, имя, аватар). Фильтр по диапазону `event.starts_at` применяется на сервере через inner-join на `events`; параметры `from` и `to` (YYYY-MM-DD) опциональны и расширяются до границ дня. _(В 39.4 inner-join заменён на left-join, чтобы в выдачу попадали и медиа без события.)_
- ✅ 38.2 DTO: `TeamMediaEventInfo`, `TeamMediaItemDto` (= `MediaItemDto` + `event: TeamMediaEventInfo`), `TeamMediaResponse { items: TeamMediaItemDto[] }`. В `api.ts` рядом с существующими медиа-типами. _(В 39.4 `event` становится nullable.)_
- ✅ 38.3 Хук `useTeamMedia({from, to})` — `useQuery` с ключом `['team-media', from, to]`. Хук `useDeleteTeamMedia()` — мутация принимает `{mediaId, eventId}`, вызывает существующий `DELETE /api/events/[id]/media/[mediaId]` (права и проверки уже там), инвалидирует `team-media`, `event-media` и `event`. _(В 39.4 переходит на собственный endpoint без `eventId`.)_
- ✅ 38.4 `MediaTile`: аватарка загрузившего перенесена из левого нижнего угла в правый — по запросу пользователя; изменение глобальное и применяется и на странице медиа события.
- ✅ 38.5 `MediaViewer`: добавлен опциональный проп `renderHeader(index)` — кликабельная панель в шапке просмотрщика с информацией о текущем медиа. Плашка ошибки шеринга сдвинута ниже при активной шапке, чтобы не наезжала.
- ✅ 38.6 Компонент `date-range-filter.tsx` — два поля `input[type=date]` («От» / «До») в одной карточке с разделителем и кнопкой «Сбросить» (показывается при активных значениях). _(В 39.5 переезжает в bottom sheet, на экране остаётся только чип-кнопка.)_
- ✅ 38.7 Экран `/squad/media/page.tsx`: `LightHeader` «Медиа» с кнопкой назад (на хаб при отсутствии истории); сверху — `DateRangeFilter`, ниже — заголовок «Все фото» со счётчиком и `MediaGrid` с аватарками авторов. Пустые состояния для отсутствия медиа и для пустого результата фильтра разведены. Просмотрщик `MediaViewer` показывает в шапке кликабельную панель с названием события, датой/временем и площадкой; тап ведёт на `/events/[id]`. Удаление — автор или организатор (через `useMe.memberships.role`).
- ✅ 38.8 Пункт «Медиа» в хабе раздела «Команда» (`/squad/page.tsx`) теперь ведёт на `/squad/media` вместо заглушки «Скоро».
