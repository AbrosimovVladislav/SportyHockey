# v0.3 — Прочие секции раздела «Команда»

**Цель:** закрыть оставшиеся секции раздела «Команда» поверх готового «Состава» (v0.2): главная раздела (хаб), Статистика, Тактика, Медиа, Настройки команды.

Раздел «Команда» (4-й нижний таб, бывший «Состав») получает **главную страницу-хаб** по образцу страницы события `/events/[id]`: шапка, сводка по команде, ближайшее событие и список секций. Сами секции (Статистика / Тактика / Медиа / Настройки) дозаполняются по итерациям; до реализации каждая открывает заглушку «Скоро».

**Итерации:** 36, 37, 38, 39, 40 (сквозная нумерация; v0.2 закрылась на 35). Порядок 37→40 предварительный — подвинем по фидбеку пилотов. Тактика идёт последней как наименее проработанное направление (добрейнштормим перед стартом).

## ✅ Итерация 38 — Медиа (общая галерея команды)

Эпик: [features/media.md](../features/media.md)

Общая галерея команды поверх готового медиа-функционала событий (v0.1) — лента всех медиа со всех событий в одном месте. Загрузка остаётся только на странице события (медиа привязано к событию), в общей галерее — просмотр и удаление. Права на удаление те же, что в событии: автор медиа или организатор.

- ✅ 38.1 API `GET /api/teams/me/media?from=&to=` (`requireUser` + `getUserTeamId`): возвращает все медиа команды с информацией о событии (id, тип, название, `starts_at`, `ends_at`, площадка) и о загрузившем (id, имя, аватар). Фильтр по диапазону `event.starts_at` применяется на сервере через inner-join на `events`; параметры `from` и `to` (YYYY-MM-DD) опциональны и расширяются до границ дня.
- ✅ 38.2 DTO: `TeamMediaEventInfo`, `TeamMediaItemDto` (= `MediaItemDto` + `event: TeamMediaEventInfo`), `TeamMediaResponse { items: TeamMediaItemDto[] }`. В `api.ts` рядом с существующими медиа-типами.
- ✅ 38.3 Хук `useTeamMedia({from, to})` — `useQuery` с ключом `['team-media', from, to]`. Хук `useDeleteTeamMedia()` — мутация принимает `{mediaId, eventId}`, вызывает существующий `DELETE /api/events/[id]/media/[mediaId]` (права и проверки уже там), инвалидирует `team-media`, `event-media` и `event`.
- ✅ 38.4 `MediaTile`: аватарка загрузившего перенесена из левого нижнего угла в правый — по запросу пользователя; изменение глобальное и применяется и на странице медиа события.
- ✅ 38.5 `MediaViewer`: добавлен опциональный проп `renderHeader(index)` — кликабельная панель в шапке просмотрщика с информацией о текущем медиа. Плашка ошибки шеринга сдвинута ниже при активной шапке, чтобы не наезжала.
- ✅ 38.6 Компонент `date-range-filter.tsx` — два поля `input[type=date]` («От» / «До») в одной карточке с разделителем и кнопкой «Сбросить» (показывается при активных значениях).
- ✅ 38.7 Экран `/squad/media/page.tsx`: `LightHeader` «Медиа» с кнопкой назад (на хаб при отсутствии истории); сверху — `DateRangeFilter`, ниже — заголовок «Все фото» со счётчиком и `MediaGrid` с аватарками авторов. Пустые состояния для отсутствия медиа и для пустого результата фильтра разведены. Просмотрщик `MediaViewer` показывает в шапке кликабельную панель с названием события, датой/временем и площадкой; тап ведёт на `/events/[id]`. Удаление — автор или организатор (через `useMe.memberships.role`).
- ✅ 38.8 Пункт «Медиа» в хабе раздела «Команда» (`/squad/page.tsx`) теперь ведёт на `/squad/media` вместо заглушки «Скоро».
- ✅ 38.9 i18n: ключи `teamMedia.*` (заголовок экрана, лейблы фильтра, пустые состояния, фолбэк-заголовки для событий без названия).

## Итерация 39 — Настройки команды

Эпик: [features/team.md](../features/team.md)

Экран `/squad/settings`: параметры команды и фото для шапок.

- Параметры команды: название, логотип, роли/доступы.
- **Фото для шапок (`DarkHeader`: «Команда», «Расписание», событие).** Организатор загружает картинку для блоков шапки своей команды; сейчас зашиты статичные `/team.png`, `/bus.png`, `/arena.png`. Кадрировщик с фиксированной рамкой (как `AvatarCropper` из 28.4), на выходе нормализованная картинка.
  - Блок шапки рендерится `cover` на всю ширину × `252px + опасная зона` (≈ квадрат, чуть шире, зависит от устройства). Рекомендация загрузки: **4:5 (вертикальное), субъект по центру с запасом ~20% сверху/снизу, минимум ~1440×1800 px, JPG/WebP.** При 4:5 картинка всегда показывается на всю ширину (по бокам не режется), подрезается только верх/низ.
