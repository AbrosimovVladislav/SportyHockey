# SportyHockey

Операционная система для организаторов любительских хоккейных команд. Telegram Mini App + бот, одна Next.js-кодбаза, Supabase для данных и медиа.

## Документация — что читать новому Claude

Перед началом работы пройди по этим пяти файлам:

### Архитектура → [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

Mini App + backend в одном Next.js-проекте на Vercel. Supabase — Postgres и Storage. Бот = тот же `@sporty_hockey_bot` (webhook в `/api/bot`), библиотека grammy. Auth — Telegram `initData` с HMAC-проверкой на каждом запросе, без JWT/cookies. Подробно — стек, структура папок, поток авторизации, модель данных.

### Best practices → [docs/BEST_PRACTICES.md](docs/BEST_PRACTICES.md)

Как работать с Claude Code в этом проекте: MCP-серверы (context7, supabase), тактики против факапов, управление контекстом, чеклист на каждый день.

### Дизайн-система → [docs/DESIGN.md](docs/DESIGN.md)

DRAFT. Опирается на CSS-переменные темы Telegram (`var(--tg-theme-*)`) — тёмная/светлая адаптируется автоматически. Конкретные значения уточнятся, когда пойдут экраны.

Оглавление версий v0.0 → v1.0 со статусами и списками эпиков. Внутри каждой версии — отдельный файл с итерациями и пунктами (сквозная нумерация 1.x → N.x).

## Конвенции

- TypeScript strict, без `any`. Если нужен — `// FIXME:type` + причина.
- Файлы < 300 строк. Одна ответственность.
- API-запросы — в `src/api/`, никогда не из компонентов.
- Стейт: серверный → TanStack Query; UI-стейт → Zustand; локальный → useState.
- Цвета/отступы/шрифты — из `src/theme/`. Никакого хардкода hex или `marginTop: 14`.
- Тач-таргеты ≥ 44px.
- Тексты пользователю — через `src/i18n/ru.ts`.
- Именование: компоненты PascalCase, хуки/утилиты camelCase, файлы kebab-case.
- Импорты абсолютные через `@/`.

## Запреты

- Не пушить в `main` без явного указания.
- Не использовать `any` без `// FIXME:type` и причины.
- Не коммитить секреты (`.env*`, ключи в коде). В репо — только `.env.example`.
- Не удалять файлы и не делать `git`-операции (`reset --hard`, `push --force`, удаление веток) без явного подтверждения.
- Не предлагать RN-абстракции или мономорфный фронт на PoC.
- Не закладывать платежи на PoC (по решению пользователя).
- Не вызывать Supabase напрямую из React-компонентов — только через `/api/*`.
- Service-role ключ — только в server-only коде (`lib/supabase-server.ts`).
- Не предлагать JWT/cookie-сессии — auth идёт через `initData` в каждом запросе.

## Команды

```bash
pnpm dev              # Next.js dev-сервер (frontend + API)
pnpm build            # production-сборка
pnpm typecheck        # tsc --noEmit
pnpm test             # vitest

supabase start                     # локальный Postgres + Storage
supabase db reset                  # пересоздать БД локально + применить миграции
supabase gen types typescript --linked > apps/miniapp/src/types/db.ts

vercel                # деплой preview
vercel --prod         # деплой prod
```

## Workflow

1. **Plan.** Для задач, трогающих > 1 файла. Читай `docs/features/<эпик>.md` и соответствующий файл итерации в `docs/roadmap/`. Предложи план одним заходом (какие файлы, какие изменения, без кода). Пользователь говорит «ок» или «поправь Х» — итерируем максимум 1 раз, потом сразу Implement.
2. **Implement.** Реализуй по плану. На неоднозначности — спрашивай, не угадывай.
3. **Build check.** После реализации запусти `pnpm typecheck && pnpm build`. **Не** делай скриншоты, **не** проводи smoke-тесты — это делает пользователь. Экономим токены. Линтеров на PoC нет — TS-strict + build достаточно.
4. **Review.** Запусти `code-reviewer` (всегда) и `design-reviewer` (если трогал UI). Только когда пользователь подтвердил, что фича работает.
5. **Docs.** Обнови соответствующий файл итерации в `docs/roadmap/v0.X.md` (отметь `- [x]`), `docs/features/<эпик>.md`, `docs/ROADMAP.md` через скилл `update-docs`.

## Правила работы

- На неоднозначности — спрашивай, не додумывай.
- Не итерируй план многократно. Один цикл: план → ревью → ok/fix → имплементация.
- После реализации НЕ запускай dev-сервер, не делай скриншоты, не пиши smoke-тесты — пользователь тестирует сам.
